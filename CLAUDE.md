# Portfolio Command Center

Local dashboard that discovers projects from Ezboss, Ezcoder and Pew2 state, combines Git/agent evidence, and ranks projects into summaries, Today actions and an inbox.

## Boundaries and invariants

- Discovery stays read-only. Agent desk is an explicit opt-in exception: operator-approved assignments create app-owned Git worktrees, launch local ACP sessions and run approved checks. Never exercise it against real projects or paid agents without explicit authorization; use isolated fixtures. Worktrees are not security sandboxes. Overrides, runs, evidence and reviews belong in app SQLite. Keep the server loopback-only and protect execution routes with the existing CSRF/origin guard (`src/agents/`, `src/server/agent-routes.ts`).
- Meetings are a second opt-in exception (`src/meetings/`, `src/server/meeting-routes.ts`): with a Fathom key saved, the server polls Fathom's read-only API every 5 minutes (started only from the server entry point, never in tests). The key lives only in the Keychain (`com.dave.meetings.fathom`). Transcripts go to the model only with the analysis switch on at the current disclosure version, or per meeting with explicit consent; the 6-hourly follow-up check needs the switch. Never close a promise automatically: evidence only suggests "Looks done?". Meeting Inbox rows are re-added inside `refresh()`'s save step (`applyMeetingAttention`), because `reconcileAttention` switches off every row of each observed project. Tests use a fake Fathom and a fake model.
- Voice is a third opt-in exception (`src/voice/`, `src/server/voice-routes.ts`, `src/ui/voice/`). The server mints an ephemeral Realtime secret with the Keychain ChatGPT token from `providers.realtimeAccess()`, called only on an explicit voice start. That token never reaches the browser, logs or responses. Never read `~/.codex/auth.json` and never fall back to API-key billing. Every model-facing string goes through `speakable()` (`src/voice/safety.ts`). Meeting transcripts and verbatim quotes never go to voice. Every write tool only prepares until the server-side confirm token (single-use, session-bound, 120 s) is accepted, unless the user turned on Approve all for that live session. Approve all is switched on only by a click (`POST /api/voice/sessions/:id/approval`) or by `approve_session` when `grantsApproval()` (`src/voice/approval.ts`) passes on `userWords`, the user's own last words. App notes, documents and tool results must never be sent as `userWords`. Approval is in memory and per session, and ends with the session. Agent desk, Fathom keys, OpenAI connect/disconnect and hiding projects must not become voice tools. Tests use a fake fetch/provider; never call OpenAI or the Keychain.
- Clean up (`src/triage/`, `src/server/triage-routes.ts`, `/api/triage` is guarded) is user-initiated only; never run it automatically. Clearing never deletes: a meeting item becomes `dropped` with source `user`, which re-analysis keeps. One decision applies everywhere in one transaction: the meeting item, its linked inferred plan items (only when every meeting source is closed; locked items and items with `human` or `delivery-plan` provenance are kept and reported) and their pending decisions. `apply` acts only on keys that still classify at that moment. Every batch is stored in `triage_batches` (schema v14), and Undo restores only rows still exactly as the batch left them. When the user closes a meeting item, `reconcile.ts` closes its inferred, unlocked plan item directly instead of drafting a decision. Rejecting a "Confirm commitment" decision drops its open meeting promises (`onCommitmentRejected`).
- Meetings v2 is selective (`src/meetings/obligation.ts`, `PROMPT_VERSION = 'meetings-v2'`): hedged, brainstormed or unagreed statements are stored as `tentative` ideas. Tentative items never create Inbox rows, follow-up checks, roadmap promises or plan commitments (`reconcile.meetingFact` returns null). A user choice (`strength_source = 'user'`, `POST /api/meetings/items/:id/strength`) survives re-analysis. Demoting obsoletes only an inferred, unlocked plan item and logs "Reclassified as an idea"; promoting reverses only that marked reclassification. Anything closed on purpose stays closed and gets a "Confirm commitment again" decision instead.
- The work watcher (`src/work/`, `/api/intel/work` is guarded) is read-only and starts only from the server entry point (`startWorkWatcher`), never in tests. Every 60 s it reads EZ Coder session heads (16 KB) and tails (64 KB) through `readOnlyFs`, maps worktrees through git's own `.git`/`gitdir`/`commondir` pointer files, and runs only the allow-listed `rev-parse HEAD` and one fixed `log` argv. GitHub is off until the owner switches it on in Connections (consent recorded in `work_settings`). It then runs `gh pr list --state merged` every 10 minutes through fixed absolute `gh` paths with argument arrays, only for repos whose `.git/config` mentions github.com, and never throws. Work evidence moves plan items only to `implementation_observed`, never `verified`. Each event gets a stored progress report (`work_progress.at` is when DAVE observed it).
- Prepared next actions (`src/intel/prepare.ts`, `src/intel/next.ts`, `/api/intel/next`) and the recommendation ledger (`src/intel/ledger.ts`, `/api/intel/recommendations`) only change DAVE's own records: decisions, steps, dates, demo marks, promise status, and skip/defer. DAVE never starts work. `hand_to_ezcoder` is descriptive only, and `POST /api/intel/next/:id/act` refuses it with 409 (`REFUSE_EXECUTION`). Only Pew starts EZ Coder, after a spoken yes. `src/` must never call Pew2 (`test/no-execution-through-pew.test.ts`). The review only suggests direction changes; a suggestion is applied only by an explicit owner request, re-computed at that moment.
- `GET /api/intel/briefing?caller=pew|voice|ui` is the only GET that writes. It upserts that caller's `briefing_cursors` row (DAVE's own bookkeeping), so "since you last asked" survives restarts of DAVE and Pew2. A caller-less GET writes nothing. The window is clamped to 14 days and defaults to 24 h. Pew2 writes to DAVE only through its allow-listed, confirm-gated POSTs (triage preview/apply/undo, `next/:id/act`, suggestion apply), with CSRF and an exact Origin.
- Shared documents (`src/documents/`, `src/server/document-routes.ts`) are the only guarded route with a non-JSON body: `config: { upload: true }` allows `application/octet-stream` up to 25 MB, and every other guarded route keeps the 64 KB JSON ceiling (`src/server/request-guard.ts`). Types are sniffed from bytes. Files stay under `PCC_HOME/documents`. Text extraction runs only on upload, through fixed absolute macOS binaries with argument arrays; nothing uploaded is executed. Discovery and refresh never touch documents.
- Direction (`src/intel/direction-store.ts`) adds named, deterministic reasons in `prioritizeProject` (`owner_focus`, `owner_priority`). With no direction set, ranking must stay identical.
- Ezcoder discovery must not open `projects.json`: it is explicitly credential-denied, not a project inventory. Supported discovery paths are defined in `sourcePaths()` (`src/shared/paths.ts`).
- `PCC_HOME` relocates only application storage (`pcc.db`); it does not relocate external discovery sources. Tests isolating all sources need an explicit fixture `home` passed to `sourcePaths()` (`src/shared/paths.ts`, `src/db/index.ts`).
- Opening an existing pre-v3 database drops legacy setup tables and clears snapshots, inbox items and adapter issues. Merely starting the server performs this migration; use fixture storage when investigating old schemas (`src/db/index.ts`, `src/server/index.ts`).
- Portfolio assembly ranks cheap facts before deep-scanning only a capped set of active, non-hidden projects. Other projects can retain cached or empty summaries; Today and new inbox events derive only from the active set. Preserve this distinction when changing ranking or summary freshness (`src/model/build.ts`, `src/model/refresh.ts`).

## Local development

- Run `npm run server` and `npm run dev` in separate terminals for API plus hot-reloading UI. Vite proxies `/api` to port 4317; changing backend `PORT` also requires changing that proxy (`vite.config.ts`).
- The backend serves built `dist`, not live UI source. `npm start` builds first; the server-only script can serve stale assets or no UI if no build exists (`package.json`, `src/server/index.ts`).
